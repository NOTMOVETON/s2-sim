<objective>
## Goal
Все изменения мира идут через буфер команд. Команды накапливаются потокобезопасно и применяются атомарно в начале каждого тика (PHASE 0). SimBus получает полный набор формальных типов событий.

## Purpose
Thread-safety фундамент: REST-поток и будущий HTTP-транспорт пишут команды, симуляционный поток читает. Без этого Phase 4 (REST API) не может безопасно изменять мир во время работы симуляции.

## Output
- `kernel_command.hpp` — std::variant со всеми типами команд
- `command_queue.hpp` — потокобезопасная очередь (mutex + std::queue)
- `sim_bus.hpp` — расширен формальными event types из спеки
- `sim_engine.hpp` — метод `enqueue()`, поле `command_queue_`, PHASE 0 в `tick()`
- `test_kernel_commands.cpp` — тесты применения команд в начале следующего тика
</objective>
