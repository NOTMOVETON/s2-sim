# Задача 20.2 — Физика движения на наклонной поверхности

## Цель

Расширить GravityPlugin: добавить гравитационную силу вдоль склона и модель трения.

Текущий GravityPlugin является **позиционным контроллером** — он удерживает Z-координату
агента на поверхности, но не моделирует силу тяготения вдоль наклона. Из-за этого:

- Робот не ускоряется при спуске с рампы (gravity не добавляет горизонтальной скорости).
- Робот не замедляется при подъёме (нет силы сопротивления вдоль склона).
- Робот может стоять на крутом склоне без движения — физически некорректно.

## Зависимости

- Задача 20 (CollisionSystem, `find_support_surface()`) — завершена.
- Задача 21 (GravityPlugin) — завершена.

## Статус: ЗАВЕРШЕНА

## Принятые решения

| Вопрос | Решение |
|--------|---------|
| Источник нормали поверхности | `find_support_surface` возвращает `SupportInfo{ground_z, normal}` |
| Модель трения | Линейная: `(1 - friction_coef)` масштабирует эффект гравитации вдоль склона |
| Кап скольжения при движении | `slide <= drive_speed * (1 - friction_coef)` — робот ВСЕГДА поднимается если friction > 0 |
| Кап скольжения стоя | `slide <= max_fall_speed` — свободное скатывание |
| По умолчанию | `friction_coef: 0.0` — обратная совместимость, полное скольжение |
| Разделение | `max_slope_rad` = проходимость (collision), `friction_coef` = скольжение (gravity) — разные концепции |

## Архитектура

### Линейная модель трения с двухрежимным капом

**Файл:** `workspace/s2_plugins/include/s2/plugins/gravity.hpp`

Модель:
1. Вычислить тангенциальную гравитацию: `g_t = g - (g . n) * n`
2. Накапливать скольжение: `slide_velocity += g_t * (1 - friction_coef) * dt`
3. Кап зависит от режима:
   - **Едет** (`drive_speed > 0`): `slide <= drive_speed * (1 - friction_coef)`
   - **Стоит** (`drive_speed ~ 0`): `slide <= max_fall_speed`
4. На плоском полу (`g_t = 0`): slide сбрасывается
5. В воздухе: slide сбрасывается
6. Slide добавляется к body velocity через `R^T * slide_world`

```cpp
if (grounded)
{
    fall_velocity_ = 0.0;
    agent.world_pose.z = ground_z;

    const Vec3& n = support->normal;
    Vec3 g_vec{0.0, 0.0, -gravity_accel_};
    double g_dot_n = g_vec.dot(n);
    Vec3 g_tangential = g_vec - g_dot_n * n;
    double g_t_mag = g_tangential.norm();

    if (g_t_mag > 1e-6 && friction_coef_ < 1.0 - 1e-9)
    {
        slide_velocity_ += g_tangential * (1.0 - friction_coef_) * dt;

        // Скорость привода (DiffDrive перезаписывает velocity каждый тик)
        double drive_speed = std::sqrt(
            agent.world_velocity.linear.x() * agent.world_velocity.linear.x() +
            agent.world_velocity.linear.y() * agent.world_velocity.linear.y());

        double slide_speed = slide_velocity_.norm();
        if (drive_speed > 1e-6)
        {
            // При движении: slide <= drive * (1-friction)
            // Гарантия: net >= drive * friction > 0
            double max_slide = drive_speed * (1.0 - friction_coef_);
            if (slide_speed > max_slide)
                slide_velocity_ *= max_slide / slide_speed;
        }
        else
        {
            // Стоя: slide <= max_fall_speed
            if (slide_speed > max_fall_speed_)
                slide_velocity_ *= max_fall_speed_ / slide_speed;
        }
    }
    else
    {
        slide_velocity_ = Vec3::Zero();
    }

    // Slide -> body frame (поверх DiffDrive)
    if (slide_velocity_.squaredNorm() > 1e-12)
    {
        Eigen::Matrix3d R = CollisionSystem::rotation_from_pose(agent.world_pose);
        Vec3 slide_body = R.transpose() * slide_velocity_;
        agent.world_velocity.linear.x() += slide_body.x();
        agent.world_velocity.linear.y() += slide_body.y();
    }
}
```

### Двухрежимный кап — обоснование

**Проблема**: при линейном накоплении `slide_velocity_` без привязки к скорости
привода, slide рано или поздно превышал drive velocity — робот скатывался назад
даже при активном движении.

**Решение**: кап зависит от состояния робота:
- **При движении**: `max_slide = drive_speed * (1 - friction_coef)`.
  Worst case: `slide_body.x = -slide_speed`. Тогда `net_x = drive - slide >= drive * friction > 0`.
  Робот ВСЕГДА поднимается если `friction_coef > 0`, даже при drive = 0.1 м/с.
- **Стоя**: `max_slide = max_fall_speed`. Свободное скатывание до терминальной скорости.

**Определение drive_speed**: `sqrt(vx^2 + vy^2)` из `agent.world_velocity.linear` —
это velocity, установленная DiffDrive ДО GravityPlugin (DiffDrive перезаписывает
velocity каждый тик).

## Математика: разложение гравитации на склоне

```
Вектор гравитации:         g  = (0, 0, -g)
Нормаль поверхности:       n  (нормализована, nz > 0)
Нормальная составляющая:   g_n = (g . n) * n
Тангенциальная:            g_t = g - g_n

|g_t| = g * sin(theta)    где theta -- угол наклона от горизонтали
|g_n| = g * cos(theta)

Ускорение скольжения:  a = g_t * (1 - friction_coef)
```

Пример для рампы 18.4 deg (atan(1/3)):
- `|g_t| ~ 3.10 м/с^2` — ускорение вдоль склона
- friction=1.0: slide=0 всегда — полное сцепление
- friction=0.5: slide растёт на 50% от g_t — умеренное скольжение
- friction=0.0: slide растёт на 100% от g_t — полное скольжение (лёд)
- Плоский пол: g_t=0 — slide=0 — привод работает нормально
