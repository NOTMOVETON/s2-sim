# Задача 20.2 — Физика движения на наклонной поверхности

## Цель

Расширить GravityPlugin: добавить гравитационную силу вдоль склона и статическое трение.

Текущий GravityPlugin является **позиционным контроллером** — он удерживает Z-координату
агента на поверхности, но не моделирует силу тяготения вдоль наклона. Из-за этого:

- Робот не ускоряется при спуске с рампы (gravity не добавляет горизонтальной скорости).
- Робот не замедляется при подъёме (нет силы сопротивления вдоль склона).
- Робот может стоять на крутом склоне без движения — физически некорректно.

## Зависимости

- Задача 20 (CollisionSystem, `find_support_surface()`) — завершена.
- Задача 21 (GravityPlugin) — завершена.

## Принятые решения

| Вопрос | Решение |
|--------|---------|
| Источник нормали поверхности | Расширить `find_support_surface` — вернуть нормаль хитовой грани вместе с Z |
| Как получить нормаль в raycast | В `ray_down_vs_box`: отслеживать ось, давшую `tmin`; нормаль = ось ± в мировых координатах |
| Как применять гравитацию вдоль склона | Разложить вектор `(0,0,-g)` на нормальную и тангенциальную составляющие; применить тангенциальную к `world_velocity.linear` |
| Z-координата | Позиционный контроль остаётся (grounded snap); тангенциальная сила применяется только к XY |
| Статическое трение | Параметр `friction_coef` в конфиге GravityPlugin; если `g*sin(θ) <= g*cos(θ)*friction_coef` — тангенциальная сила не применяется |
| По умолчанию | `friction_coef: 0.0` — обратная совместимость, поведение без трения |

## Архитектура

### Шаг 1 — Расширить возвращаемый тип `find_support_surface`

Текущая сигнатура:
```cpp
std::optional<double> find_support_surface(const Vec3& position, double bounding_radius) const;
```

Новый struct и сигнатура (в `collision_system.hpp`):
```cpp
struct SupportInfo
{
    double ground_z;   ///< Z на которой должен стоять агент (поверхность + bounding_radius)
    Vec3   normal;     ///< Нормаль поверхности в мировых координатах (нормализована)
};

std::optional<SupportInfo> find_support_surface(
    const Vec3& position, double bounding_radius) const;
```

Внутренние raycast-функции тоже меняют тип возврата:
```cpp
// было
std::optional<double> ray_down_vs_box(...) const;
std::optional<double> ray_down_vs_cylinder(...) const;
std::optional<double> ray_down_vs_sphere(...) const;

// стало
struct RayHit { double z; Vec3 normal; };
std::optional<RayHit> ray_down_vs_box(...) const;
std::optional<RayHit> ray_down_vs_cylinder(...) const;
std::optional<RayHit> ray_down_vs_sphere(...) const;
```

### Шаг 2 — Нормаль хитовой грани в `ray_down_vs_box`

В slab-методе отслеживать, какая ось дала `tmin` (вход в box). Нормаль = эта ось, со знаком
направленным от box к лучу.

```cpp
// Добавить к slab-loop:
int   tmin_axis = -1;
double tmin_sign = 1.0;

for (int i = 0; i < 3; ++i) {
    double d = local_dir[i];
    double o = local_orig[i];
    double h = half[i];

    if (std::abs(d) < 1e-12) {
        if (o < -h || o > h) return std::nullopt;
    } else {
        double t1 = (-h - o) / d;
        double t2 = ( h - o) / d;
        bool swapped = t1 > t2;
        if (swapped) std::swap(t1, t2);
        if (t1 > tmin) {
            tmin = t1;
            tmin_axis = i;
            // Знак нормали: луч входит в box с той стороны, откуда он пришёл.
            // Нормаль направлена НАРУЖУ от box к лучу.
            tmin_sign = swapped ? 1.0 : -1.0;
        }
        tmax = std::min(tmax, t2);
        if (tmin > tmax) return std::nullopt;
    }
}

// ... вычисление t, hit_local, hit_world ...

// Нормаль хитовой грани в локальных координатах box
Vec3 local_normal = Vec3::Zero();
if (tmin_axis >= 0)
    local_normal[tmin_axis] = tmin_sign;
else
    local_normal = Vec3{0, 0, 1};  // fallback: top face

Vec3 world_normal = (R * local_normal).normalized();
return RayHit{hit_world.z(), world_normal};
```

Проверка знака на конкретном примере:
- Горизонтальный пол, луч сверху вниз: `local_dir.z < 0`, tmin от оси Z, `swapped = false`
  (t1 < t2), `tmin_sign = -1.0` → `local_normal.z = -1.0`...
  
  **Внимание**: `tmin_sign` должен указывать от поверхности к источнику луча (к агенту).
  Луч идёт вниз (`d[2] < 0`), значит он входит со стороны +Z → нормаль = (0, 0, +1).
  
  Уточнённое правило: `tmin_sign = (local_orig[i] >= 0) ? 1.0 : -1.0`, то есть нормаль
  смотрит в сторону, откуда пришёл луч:
  ```cpp
  tmin_sign = (local_orig[i] >= 0.0) ? 1.0 : -1.0;
  ```

Для цилиндра (нет поворота по pitch/roll в типичном использовании): нормаль верхней крышки
= (0, 0, 1) в локальных, преобразованная через R.

Для примитива-сферы: нормаль = `(origin - sphere_center).normalized()` в точке пересечения
(уже направлена от центра, т.е. от поверхности к лучу).

### Шаг 3 — GravityPlugin: тангенциальная сила

**Файл:** `workspace/s2_plugins/include/s2/plugins/gravity.hpp`

Добавить параметр `friction_coef_` и логику разложения гравитации.

В `from_config`:
```cpp
friction_coef_ = node["friction_coef"].as<double>(0.0);
```

В `update` после определения `grounded`:
```cpp
if (grounded)
{
    fall_velocity_ = 0.0;
    agent.world_pose.z = support->ground_z;

    // Тангенциальная составляющая гравитации вдоль склона
    const Vec3& n = support->normal;
    Vec3 g_vec{0.0, 0.0, -gravity_accel_};
    Vec3 g_normal     = g_vec.dot(n) * n;
    Vec3 g_tangential = g_vec - g_normal;   // вектор в направлении "вниз по склону"

    // Проверка статического трения:
    // Скользим если |g_tangential| > friction_coef * |g_normal|
    // (аналог tan(θ) > μ_s)
    double g_t_mag = g_tangential.norm();
    double g_n_mag = std::abs(g_vec.dot(n));   // > 0, т.к. нормаль смотрит вверх

    bool slides = (friction_coef_ < 1e-9) ||
                  (g_t_mag > friction_coef_ * g_n_mag);

    if (slides)
    {
        // Применяем тангенциальное ускорение к горизонтальной скорости
        // (только XY — Z управляется позиционной коррекцией выше)
        agent.world_velocity.linear.x() += g_tangential.x() * dt;
        agent.world_velocity.linear.y() += g_tangential.y() * dt;
    }
    else
    {
        // Статическое трение удерживает — гасим горизонтальную скорость
        // пропорционально, чтобы остановить дрейф
        agent.world_velocity.linear.x() *= 0.0;
        agent.world_velocity.linear.y() *= 0.0;
    }
}
```

> **Почему XY, а не полный вектор**: Z-координата управляется позиционным контролем
> (`pose.z = ground_z`). Применять тангенциальную силу по Z — значит дублировать snap.
> Поэтому применяем только горизонтальные компоненты к `world_velocity`, а Z обнуляем.

### Шаг 4 — Обновить вызов в `update` GravityPlugin

Т.к. `find_support_surface` теперь возвращает `SupportInfo`:

```cpp
// было
auto support = collision_->find_support_surface(agent.world_pose.position(), agent.bounding.radius);
const double ground_z = support ? *support + agent.bounding.radius : ...;

// стало (SupportInfo уже содержит ground_z с учётом bounding_radius)
auto support = collision_->find_support_surface(agent.world_pose.position(), agent.bounding.radius);
// support->ground_z уже = поверхность + bounding_radius (вычисляется внутри)
```

Или `find_support_surface` по-прежнему возвращает Z поверхности, а `ground_z` вычисляется
снаружи — решить при реализации, чтобы не менять контракт больше необходимого.

Рекомендуется: `SupportInfo.ground_z = hit_z` (Z поверхности, не центра), а
`ground_z = support->ground_z + bounding_radius` вычислять в плагине — это сохраняет
семантику "Z поверхности" в структуре.

## Математика: разложение гравитации на склоне

```
Вектор гравитации:         g⃗ = (0, 0, -g)
Нормаль поверхности:       n⃗  (нормализована, nz > 0)
Нормальная составляющая:   g⃗_n = (g⃗ · n⃗) * n⃗
Тангенциальная:            g⃗_t = g⃗ - g⃗_n

|g⃗_t| = g * sin(θ)        где θ — угол наклона от горизонтали
|g⃗_n| = g * cos(θ)

Условие скольжения: |g⃗_t| > μ_s * |g⃗_n|
                    g*sin(θ) > μ_s * g*cos(θ)
                    tan(θ) > μ_s
```

Пример для рампы 18.4° (atan(1/3)):
- `sin(18.4°) ≈ 0.316`, `cos(18.4°) ≈ 0.949`
- `|g⃗_t| ≈ 3.10 м/с²` — ускорение вдоль склона
- `tan(18.4°) ≈ 0.333`
- При `friction_coef = 0.5` (27°) — не скользит ✓
- При `friction_coef = 0.3` (17°) — скользит ✓
